accessibility

the goal

Accessibility is something I care about as a designer and researcher. This site aims to meet WCAG 2.1 AA ↗ standards where possible. It is an ongoing process, this pages tells you the current state on where this site stands.

how i test

I run Lighthouse accessibility audits ↗ on pages as I build them. As of this update, every page checked scores 100.

I test critical flows with VoiceOver, navigating without a mouse to hear how images, buttons, and forms actually get announced, not just whether they technically have labels.

I also do manual keyboard-only passes (tab, shift+tab, enter) to catch things automated tools miss, like the clickable blank space issue noted below.

what's in place

Semantic HTML throughout: headings, landmarks, & lists used properly rather than just for style.

All images have alt text. Decorative images are marked as such. These help with screen reader navigation.

Keyboard navigation is supported. Interactive elements like the lightbox and nav are reachable and operable without a mouse, including fixing an earlier issue where blank space could register as a clickable area.

ARIA labels are in place on icon-only buttons and links.

Color contrast between text and background meets AA ratio requirements.

The site is responsive and readable on mobile without horizontal scrolling.

known gaps

I aim to have alt tags within images be more descriptive to provide better context for screen reader users.

PDF downloads (zines) are not screen-reader accessible. This is a harder problem given the format as the aim is to allow print accesibility (anybody can have their own copy of the zine), I'm thinking through how to handle it. If you have any ideas let me know.

found something?

If you run into an accessibility issue on this site, please let me know. Click the bug button on the right side of the screen to report it. I take these seriously and will fix it as soon as possible.
