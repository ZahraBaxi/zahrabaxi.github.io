the goal

Accessibility is something I care about as a designer and researcher. This site aims to meet WCAG 2.1 AA ↗ standards where possible (WCAG is the most widely used accessibility standard for the web, and AA is the middle tier most sites and laws expect). It is an ongoing process, this page tells you the current state on where this site stands.

how i test

automated scans

I run Lighthouse accessibility audits ↗ on pages as I build them. Lighthouse is a free tool built into Chrome that scans a page and flags common issues, like text that's too low-contrast to read or elements missing labels. Every page on this site currently scores 100.

screen reader passes

I test critical flows with VoiceOver, the screen reader built into Mac and iPhone, navigating without a mouse to hear how images, buttons, and forms actually get announced out loud, not just whether they technically have labels attached. This catches things automated tools can't, since a label can exist and still be confusing or redundant when you actually hear it.

keyboard-only passes

I do manual keyboard-only passes too (tab, shift+tab, enter, no mouse at all) to catch things automated tools miss, like an earlier issue where empty space on the page could accidentally register as a clickable area.

This has already caught real things, like low-contrast text and a mislabeled icon, both since fixed.

what's in place

✓

semantic HTML throughout

Semantic HTML ↗ throughout: headings, landmarks, & lists used properly rather than just for style. This helps screen readers understand the structure of a page instead of just reading it top to bottom as one long block.

✓

descriptive alt text

All images have alt text (a short written description a screen reader can read aloud in place of the image). Decorative images that don't add meaning are marked as such, so screen readers skip over them instead of announcing something meaningless.

✓

keyboard navigation

Keyboard navigation is supported. Interactive elements like the lightbox and nav are reachable and operable without a mouse, including fixing an earlier issue where blank space could register as a clickable area.

✓

ARIA labels on icon-only elements

ARIA labels ↗ (extra bits of text that describe an element to a screen reader when the visible design alone isn't enough, like an icon-only button) are in place on icon-only buttons and links, and are checked for accuracy rather than just present for the sake of it.

✓

AA color contrast

Color contrast between text and background meets AA ratio requirements ↗, meaning there's enough difference between text and background color for people with low vision or color blindness to read comfortably.

✓

responsive on mobile

The site is responsive and readable on mobile without horizontal scrolling.

known gaps

!

more descriptive alt text

I aim to have alt tags within images be more descriptive to provide better context for screen reader users.

!

PDF zine downloads

PDF downloads (zines) are not screen-reader accessible. This is a harder problem given the format as the aim is to allow print accesibility (anybody can have their own copy of the zine), I'm thinking through how to handle it. If you have any ideas let me know.

found something?

If you run into an accessibility issue on this site, please let me know. Click the bug button on the right side of the screen to report it. I take these seriously and will fix it as soon as possible.
